# Michael's additions

Design-level ideas that Michael brought and that were kept, on top of or against Claude's proposal.
Kept by Claude as the working agreement in `CLAUDE.md` says. Newest last.

| Date | Phase | Michael proposed | Claude had proposed | Why Michael's version was kept |
| --- | --- | --- | --- | --- |
| Sep 25, 2026 | 1 | Record real Gemini and Voyage responses from the first real call on, and replay them in later tests and demos, so the app is mostly exercised against recorded vendor output rather than live calls | Fake adapters only for tests (deterministic, no vendor), an in-memory cache for query embeddings in Phase 4; no record/replay of real responses | Live output is the ground truth for search quality; recording it makes the live test and the query matrix repeatable and free after the first run, and the spike's raw responses become fixtures instead of being thrown away |
| Sep 25, 2026 | 1 | An ordered list of Gemini models in config; when one answers with high demand, the adapter moves on to the next one in the list | One model id in `VISION_MODEL`; transient errors retried with backoff on that same model | Gemini's preview and Flash models are regularly overloaded; a second model answering now beats waiting out backoff on the first, and the list is ops-tunable without a code change |
| Sep 25, 2026 | 1 | Use only older Flash models, for price; only models that generate content. List: [`gemini-3-flash-preview`, `gemini-3.1-flash-lite-preview`, `gemini-3.1-flash-lite`, `gemini-3.5-flash-lite`] | "Gemini Flash (current 3.x)" in the design, default `gemini-3-flash`; the list itself was Claude's recommendation within Michael's rule | The newest Flash models cost more for no gain the spike could see: the older `gemini-3.1-flash-lite-preview` honoured the schema and read the screenshot's text correctly. The spike showed the 2.5 models are refused to new keys, so the 3.x previews are the oldest usable |
| Sep 26, 2026 | 1 | Make the recorded collection the cornerstone of testing: design the collection early, run it once through the real pipeline, store every result, and commit the recordings | Collection designed in Phase 5; whether recordings are committed left to Phase 5. Claude's contribution: record through the Phase 3 worker rather than Phase 1's CLI, so replays hit byte-identical requests | Meaningful tests need real model output; recording it once and committing it makes every later test and demo realistic, repeatable and free |
